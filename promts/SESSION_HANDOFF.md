## 2. Правила работы пользователя и репозитория

- Коммуникация и UI — на русском.
- Перед реализацией спорной архитектуры сначала анализ и ревью структуры.
- Названия форм и URL-маршруты сохраняются прежними, как в legacy.
- Публичные и protected API документируются XML `/// <summary>`.
- Commit/push в рамках согласованной задачи разрешены; merge — только после явного
  одобрения пользователя.
- После изменений в сабмодулях обязательно обновлять ссылки в суперпроекте.
- AGENTS.md и документацию не менять без отдельного прямого указания.
- SQL Server 2008 R2: только совместимый SQL, параметры через Dapper, никакой
  подстановки значений в SQL-строку.
- Данные гридов и справочников — серверные: поиск, сортировка, пагинация.
- При загрузке в Blazor использовать `OnAfterRenderAsync`, избегать двойной загрузки
  из prerendering.
- Новые UI-контролы делать общими только при реальном повторном использовании,
  без спекулятивных абстракций.

### Контракт

`ClaySelect<TItem, TValue>`:

- `TItem : class`;
- `TValue` должен допускать `null` (`int?`, `Guid?`, ссылочный тип);
- `Value` — источник истины, `SelectedItem` синхронизируется по ID;
- `DataSource` имеет приоритет над `Items`;
- источник получает `Limit=MaxItems`, возвращает максимум Limit и отдельный `HasMore`;
- `ValueSelector` и `TextSelector` обязательны;
- `ItemTemplate` поддерживается;
- nullable `TValue` означает, что `0` и `Guid.Empty` — допустимые ID;
- `ClearAsync` очищает выбор без последующего восстановления по Escape.

### Поведение

- Поиск выполняется **только** по Enter, blur или кнопке «…», не при вводе.
- Debounce убран. Ввод только меняет текст и инвалидирует старую выдачу.
- Enter на неизменном выбранном значении — no-op, без popup и повторных callbacks.
- Автовыбор выполняется только при доказанной уникальности совпадения.
- При неизменном выбранном значении расширенный поиск получает пустой `search`.
- После редактирования ESC восстанавливает прежние ID, объект и текст через
  сохранённый backup. Явная очистка backup отключает.
- Одновременно открыт только один popup; `closeOthers` централизован.
- Popup не зависит от высоты сообщений валидации.
- Направление popup определяется по фактической высоте после `max-height`,
  а не по полному `scrollHeight`; при необходимости открывается вверх.
- При scroll/resize положение пересчитывается.
- Строки уплотнены до ~24 px.
- Hover полностью CSS-only, без серверных рендеров и мерцания.
  `:has(.clay-select-option:hover)` временно подавляет прежнюю активную строку;
  после ухода мыши клавиатурная активная строка восстанавливается.
- Активная строка: `var(--mud-palette-primary)` + `var(--mud-palette-primary-text)`,
  золотая граница.
- `ViewItem` — callback просмотра сущности. При заданном обработчике после выбора
  кнопка «…» заменяется иконкой `Visibility`.
- `ViewItemAriaLabel` добавлен в `ClaySelectOptions`.

### Внешний расширенный поиск

`ClaySelectAdvancedSearchService` централизует протокол:

- URL открывается с `return=1`, `requestId`, `returnOrigin`;
- принимаются только сообщения с правильными `event.origin`, `event.source` и `requestId`;
- результат — `FromValue` или `FromItem`;
- `null` — отмена без изменения выбора;
- `cancel(requestId)` удаляет listener, timer и закрывает дочернее окно;
- `WaitAsync(cancellationToken)` + очистка в `finally`;
- `DisposeAsync` очищает все ожидания и `DotNetObjectReference`;
- Inventory передаёт cancellation token жизненного цикла страницы;
- после disposal фокус не восстанавливается.

### Гонки

- Поиск имеет версию и CTS; проверки версии выполняются после каждого await,
  включая `closeOthers` и `StateHasChanged`.
- Поздние ответы не перезаписывают новый поиск/выбор.
- Тесты гонок проверяют реальное завершение старой операции, а не только текущее
  корректное состояние.

## 4. Users и конфигурация

`Kesco.App.Web.Users`:

не поднимает эти ключи через XML provider.

| Поле | Обязательность/default | Зависимости |
|---|---|---|
| Тип оборудования | Обязателен; из `codetype`/`_codetype` или пусто | Существующий `EquipmentTypeSelectDataSource`; сортировка по ID или алфавиту |

| PN | Необязателен, max 50 | Триггер требует >=3 символов для типов 1 и 2 |
| Размер монитора | Число с precision 1; 0→пусто | Только при `ЕстьХарактеристикиМонитора` |
| Мультимедиа | false | При характеристиках монитора или компьютера |
| CPU | Необязателен, max 50 | Только при `ЕстьХарактеристикиКомпьютера` |

| НазваниеNet | max 50 | При Net=0 очищается/read-only; при Net>0 триггер требует >=3 |
| Тип памяти | Из `ТипыПамяти`, default 0 | Только при характеристиках компьютера |

| Шаблон телефона | Отдельная форма | Кнопка только для типа 30, существующей модели и роли 102; при смене типа очищается |
| Изменил/Изменено | Только чтение | Заполняются триггером |

Удаление модели в legacy закомментировано — не переносить.

### Создание и редактирование

Создание:

- `Net=0`, остальные поля пустые/нулевые;
- заголовок «Новая модель оборудования»;
- после «Применить» полученный ID записывается в URL, страница обновляется уже
  в режиме редактирования.

Редактирование:

- заголовок содержит `#id`;
- показываются `Изменил/Изменено`;
- показывается количество оборудования модели, включая списанное;
- кнопка шаблона только при выполнении условий;
- при смене типа проверяется связанное оборудование и выводится подтверждение.

Без изменений закрытие не выполняет SQL. После сохранения обновляется родительское окно;
OK закрывает, «Применить» оставляет форму открытой.

### Права

- Роль 43 `Специалист_по_инвентаризации_оборудования` — обязательна для изменения модели
  (проверяется триггером).
- Роль 102 `Дежурный_инженер` — обязательна для изменения шаблона; в code-behind
  также управляет видимостью кнопки.
- Шаблон можно менять только по одной записи и только для типа 30.

Ошибки триггера должны отображаться через `ClayErrorBar`.

### Валидация и SQL

Перед сохранением:

- выбран тип;
- указана модель;
- нет другой записи с той же парой модель+PN
  (`SELECT_МодельОборудования_EXISTS`).

При смене типа существующей модели:

- `SELECT_ID_КоличествоОборудованияМоделиДругогоТипа` проверяет связанное оборудование;
- при наличии показывается подтверждение с количеством и числом списанных;
- сохранение только после согласия.

SQL:

- создание — `INSERT_МоделиОборудования` + `SELECT @@IDENTITY`;
- обновление — `UPDATE_МоделиОборудования`;
- шаблон — `UPDATE_МоделиОборудования_ШаблонТелефона`.

Дополнительные проверки триггера:

- имя модели обязательно;
- PN для типов 1 и 2;
- `НазваниеNet` при Net>0;
- максимум сетевых интерфейсов;
- нельзя уменьшить Net ниже фактического количества MAC-адресов у связанного оборудования;
- права на модель и шаблон.

Побочные действия триггера:

- `Изменил` — сотрудник по `SUSER_SID()`;
- `Изменено` — `GETUTCDATE()`;
- нормализация примечаний;
- удаление и повторное извлечение настраиваемых атрибутов телефона через
  `sp_ИзвлечьАтрибутыТелефона`;
- очистка CR в шаблоне.

### URL и возврат

- `id` — редактируемая модель;
- `codetype` или `_codetype` — начальный тип новой модели;
- после создания `id` добавляется в URL через `SetCurrentUrlParams`.

Специального возвращаемого объекта нет: legacy сохраняет модель, обновляет родительское
окно и закрывается через `V4DropWindow`. Скрытая `mvcDialogResult` не содержит
прикладного маппинга модели. Отмена с изменениями подтверждается базовым `EntityPage`.
