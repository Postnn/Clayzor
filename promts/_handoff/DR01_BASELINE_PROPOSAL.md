# DR-01 baseline proposal — статус

## Отчёты 53–55

- `53_DR01_BASELINE_PROPOSAL`: вариант C-01/C-03 с отдельным Original и обновлением baseline через Accept. Это предложение владельцу, не завершённый общий контракт.
- `54_DR01_BASELINE_BROWSER`: тестовый host подтвердил на PhoneCode конфликт V1 → собственная правка → внешний V2 → F5, сохранность дополнительной правки и блокировку Apply; raw-only также блокируется до решения пользователя.
- `55_DR01_RAW_READINESS`: тестовый host подтвердил C-02 — отсутствующее raw-поле блокирует Apply и последующую правку; возврат поля и Обновить восстанавливают значение и разблокируют Apply.

Production `TerritorialEntityCardBase` не изменялся. Предложения 53 и 55 не интегрированы: требуется решение владельца общего API и согласованные resolve/rekey hooks для четырёх consumers. Проверены только PhoneCode и изолированные тестовые hosts. C-04/C-05, конкурентные маршруты, наложение блокировок и IIS-сценарии остаются открытыми.

## Подтверждение 56

`56_SLBL_PREFLIGHT_INTEGRATION` подтверждает опубликованный merge `5b4b855`: содержимое совпадает, сборка и SlBl 23/23 прошли. Реальная почтовая синхронизация ожидает тестовой процедуры и подтверждённого доступа.

## Отчёт 57 — C-05 route isolation

Два bUnit-теста на опубликованном `TerritorialEntityCardBase` воспроизвели дефект: позднее чтение A после показа B меняет текст A; поздняя регистрация A направляет правку B в регистрацию A.

Предложение: смена ключа отменяет загрузку, сбрасывает состояние, выделяет DOM-корень маршрута, освобождает поздние handles и сериализует повторное открытие A без задержки B. Тестовый патч проверен `git apply --check`; изолированный профиль четырёх карточек — 75/75, включая гонки чтения, регистрации, raw restore и A → B → A.

Патчи 53, 55 и 57 не интегрированы в production. Требуется согласованная интеграция всех трёх и браузерная проверка четырёх маршрутов с IndexedDB, включая историю после сохранения SIM FMTN. C-04 остаётся отдельным этапом. Записей в БД и запусков служб не было.
