## 2. URL, ключ и режимы

- Новая страница `/Equipment/SlBl_form`, совместимость `/Equipment/SlBl_form.aspx`; не меняй название произвольно на «редактор оборудования».
- Параметр `id` необязателен. Без него пользователь выбирает адрес и вид списка.
- Формат `id=ADDRESS:0` выбирает безопасный список; `ADDRESS:1` — заблокированный. При отсутствии `:` legacy делает URL decode и разбивает по U+001F, поэтому поддерживается также старый составной ключ `ADDRESS%1F0` / `ADDRESS%1F1`.
- Первая часть всегда почтовый адрес-строка. Если второй части нет, адрес выбран, но вид списка явно не установлен. В legacy любая вторая часть, отличная от `0`, попадает в ветку `1`; корректные callers формируют 0/1. В новой форме не превращай неизвестный код в запись другого списка: валидируй 0/1, показывай ошибку, зафиксируй исправление этой неоднозначности.
- URL-декодирование должно учитывать query parser: не декодируй многократно до изменения буквального адреса. Проверить `+`, `%`, `@`, разделители и encoded URL.
- После успешного сохранения/обновления legacy формирует `ADDRESS:BLOCK` и делает reload с `encodeURIComponent`. В Clayzor можно обновить состояние/URL без уничтожения circuit, сохранив выбранный адрес и вид.
- Адрес и radio в legacy не заблокированы после загрузки: строки их disable закомментированы. Не делай их read-only только потому, что форма открыта с id.

### Выбор адреса и вида

`efAddress_OnChanged` сначала выключает сохранение и скрывает список. Далее:

| Загруженные данные | Поведение legacy |
|---|---|
| Адрес очищен | Очищаются Value/OriginalValue textarea, список скрыт |
| Сущность SlBl отсутствует (`Unavailable`) | Оба списка UI пустые; вид не выбран; фокус на radio |
| SList и BList непустые | Вид не выбирается автоматически; пользователь выбирает radio |
| SList пуст | Автоматически выбран заблокированный список (в том числе когда оба списка пусты) |
| SList непустой, BList пуст | Автоматически выбран безопасный список |

Radio переключает именно содержимое выбранного списка; второе radio снимается. Загрузка фиксирует `Value == OriginalValue`, Save выключается. Изменение textarea включает Save при точном неравенстве строк; возврат к исходной строке выключает Save.

Legacy `HideListAddress` снимает DOM checked, но не во всех ветках очищает серверные radio Values. В новой реализации используйте одно типизированное состояние `selectedKind`, чтобы после смены адреса нельзя было сохранить старый тип в скрытый список. Это исправление рассинхронизации, а не новое бизнес-правило.

При переключении адреса/вида с несохранённым текстом не теряй черновик молча. В legacy явного предупреждения на этот переход нет; добавь штатное подтверждение отказа от правок и отметь эту защиту в карте отличий. Cancel такого подтверждения сохраняет и адрес, и тип, и текст.

## 4. Валидация и формат списка

- Без адреса: **«Необходимо указать E-mail адрес.»**, фокус в lookup.
- Без вида: **«Необходимо выбрать вид списка.»**, фокус в radio.
- Пустой список разрешён: это намеренное очищение выбранного вида, а не отсутствие данных. Не запрещай очистку обязательностью textarea.
- Legacy JS допускает символы из набора `- A-Z a-z 0-9 , . @ _` и пробел. Это не проверка только email: домены и полные имена серверов прямо разрешены подсказкой. Не вводи единственный email regex и не отбрасывай домены.
- Keypress и paste в legacy реализованы неодинаково; асинхронный Clipboard API может вернуть текст после самой проверки, а `return false` внутри позднего callback не отменяет вставку. Не переносить эту ошибку. Реализуй одинаковую, понятную проверку для клавиатуры/вставки/серверной команды без тихого удаления символов.
- Сначала проверь, какие разделители реально поддерживает `fn_SplitText` и действующие данные: исходники формы не раскрывают полный parser БД. Не нормализуй регистр, не сортируй и не пересобирай список перед сохранением по догадке. Показывай загруженное содержимое полностью; неподдерживаемые новые символы объясняй, не порть существующие записи.
- Сервер проверяет лимит 7950 и все обязательные параметры; клиентская маска не является защитой write-path.

## 5. SQL и доменная модель

Все запросы и DTO чтения/сравнения принадлежат Entities; источник ClaySelect — DBSelect. Никакого inline SQL в Razor/сервисе CRUD. Для процедуры синхронизации и последующей сверки допустим узкий coordinator, который не дублирует SQL и права Employee.

| Операция | Источник/параметры | Результат |
|---|---|---|
| Lookup адресов | `SELECT_SlBlAddresses`: `SELECT * FROM vwMailBoxesAddresses`; поиск по Address, порядок Address | Строковые ID/Name = Address |
| Восстановление lookup | `SELECT_ID_SlBlAddress`, `@id` string | Адрес существует только при одной найденной записи |
| Загрузка списков | `SELECT_ID_SlBlAddressList`, `@id` string, DS_user | UNION ветвей Block=0/1; GROUP BY Address; MAX(SList), MAX(BList). Ноль строк — `Unavailable`, а не транспортная ошибка |
| Синхронизация | `SP_MailboxesSlBlSynchronize` = `sp_MailboxesSlBlSynchronize`, StoredProcedure, DS_user, timeout **180 секунд** | `@AddressSet` = выбранный адрес; `@BlockSet` = 0/1; `@SlBl` = полный текст выбранного списка |
| Проверка | `SELECT_SlBlCheckSavedData`, CommandType.Text, DS_user | `@Address`, `@Block`, `@FormData`; ровно одна строка с `НеУдалено`, `НеСохранено` |

Проверочный SQL получает фактический `SLBL` из `vwMailBoxesAddressesSlBl`, разбивает через `dbo.fn_SplitText` во временную таблицу `#SavedData`, разбивает исходный текст DISTINCT в `#FormData` и вычисляет две разности множеств:

- `НеУдалено`: есть в фактическом состоянии, отсутствует в желаемом;
- `НеСохранено`: есть в желаемом, отсутствует в фактическом.

Оба списка сортируются по Address и собираются через `FOR XML PATH`/`STUFF`; это SQL Server 2008 R2 совместимый подход. Не заменять его на `STRING_AGG`. Учитывай XML escaping выдачи при отображении, не исполняй возврат БД как HTML.

Не переносить отсутствие результата, SQL timeout или ошибку проверки в состояние «списки пустые». Запись могла частично пройти; пользователь должен видеть неопределённость результата и возможность перечитать фактическое состояние.

**Конкретная зависимость текущего Clayzor:** обычный DbManager.QueryAsync может вернуть пустой набор при connectivity error, а timeout `-2` запускает общий reconnect. После успешного health-check ClayDbReconnectService делает forceLoad всей страницы, уничтожая draft и результат незавершённой сверки. Перед приёмкой SlBl используй строгие required-read/write методы и общий guard восстановления, описанные в COMMON. Отдельный catch формы недостаточен. Проверка: процедура дала timeout, `SELECT 1` затем успешен — исходные Address/Kind/Text и состояние «результат неизвестен» остаются доступны, повтор procedure сам не запускается.

## 6. Сохранение как последовательность состояний

1. Команды `Save` и `Apply` в legacy вызывают `SaveData(true)`, а `SaveData` — `SaveData(false)` после подтверждения. Это не два разных CRUD-сценария.
2. Проверить адрес, вид, длину, аутентификацию и актуальные права на адрес/операцию.
3. Подтверждение с исходными текстами: **«Данная операция может выполняться до двух минут.»**, **«Вы уверены, что хотите выполнить данную операцию?»**. Фактический SQL timeout — **180 секунд**, не 120. Не путать подсказку и настройку таймаута.
4. Зафиксировать неизменяемый снимок Address/Kind/Text для этой операции. До завершения не разрешать второй запуск и смену контекста, иначе проверка может сравнить результат чужого списка.
5. Асинхронно вызвать процедуру. Busy UI не блокирует circuit; прерывание ожидания не выдаётся за rollback серверной синхронизации.
6. Всегда выполнить проверочный SELECT после успешного вызова. Количество строк, отличное от 1, — ошибка контракта (`CheckSavedData` в legacy бросает LogicalException).
7. Если хотя бы одна разность непустая, показать **«Выполнить операцию не удалось!»**, отдельно **«Сохраненные записи, которые не удалось удалить»** и **«Новые записи, которые не удалось сохранить»**, затем **«Выполнить операцию сохранения повторно?»**. Это частичный результат; не success toast.
8. Повтор — только по явному выбору пользователя и после свежей проверки прав/контекста. Нет автоматического бесконечного retry процедуры.
9. Если обе разности пусты, показать **«Данные успешно сохранены!»**, затем **«Закрыть форму?»**.
10. «Да»: уведомить родительский список и закрыть дочернее окно. «Нет»: перечитать фактическое состояние, установить новый OriginalValue и сохранить выбранный Address/Kind. Родительский черновик не уничтожать.

Исходники не определяют дополнительную роль для SlBl. Не назначай эту функцию произвольно сетевому администратору или роли тарифов. До write проверить реальные grants/view scope/EXECUTE процедуры и общую identity через Employee; неподтверждённые ограничения доступа вынести в контракт стенда. Не принимать видимый адрес в клиентском lookup как доказательство права на запись по любому адресу.

## 7. Обновление, закрытие и конкурентные изменения

`RefreshData()` без адреса/вида обновляет страницу. При выбранном контексте заново читает SlBl и сравнивает выбранный список с текстом редактора через `ToLower().Trim()`. Если запись отсутствует или тексты отличаются — подтверждение **«Изменения не сохранены! Вы хотите заново загрузить данные?»**; после согласия reload сохраняет составной id. Это сравнение с актуальной БД, а не только с OriginalValue.

**Современное решение пользователя от 26.11.2026:** это описание legacy. В Clayzor сброс ввода с повторным чтением перенесён на Cancel→Reset по FORM-KEY-01; Refresh читает/сверяет, сохраняя draft.

Сохрани обнаружение внешнего изменения. Exact dirty и legacy Trim/ignore-case сравнение зафиксируй как разные исторические правила; не меняй SQL/данные и не нормализуй пользовательский ввод ради их унификации. Современный Refresh выполняет fresh-сверку с сохранением local/raw, отмена merge ничего не меняет. Сброс ввода с повторным чтением — Cancel→Reset по FORM-KEY-01 после успешного чтения; бинарное legacy-подтверждение Refresh не переносить.

Для write перечитай исходное состояние/контекст и не перезаписывай замеченные конкурентные правки без предупреждения. При этом не объявляй optimistic concurrency гарантированной, если stored procedure не поддерживает compare-and-set/lock/version: pre-read сам по себе не закрывает гонку. Установи реальный контракт процедуры на тестовой БД, не добавляй выдуманный rowversion или новую таблицу.

Legacy `slbl_openerRefresh()` вызывает `opener.refresh()`, затем `DropMyWindow`. В Clayzor использовать общий refresh bridge; отсутствие/закрытие родителя или другой origin не должно превращать успешное сохранение в потерю данных/ошибку формы. Отмена без записи не вызывает ложное обновление родителя. Прямое закрытие с несохранённым текстом защищается общим механизмом dirty, поскольку legacy SlBl не привязывает SB как обычный EntityPage.Entity.

Проверять синхронизацию на согласованном тестовом почтовом адресе/стенде, подтвердив фактические внешние эффекты процедуры. Нельзя использовать production-ящики как фикстуры. Моки подтверждают ветвление UI, но не успешную работу почтовой синхронизации.

## 9. Что сдать

Код страницы, Entities/read models/lookup и coordinator; карту всех handlers и SQL-параметров; точные сообщения и русские/английские ресурсы; подтверждённый access contract; тесты валидации, partial result, отказов и opener; результаты реального теста процедуры или явное ограничение среды. В handoff зафиксировать отличия: устранение устаревшего radio state, paste-race, защита черновика, правила concurrency и отмены длительного вызова. Без подтверждения второй фазы сохранение не принято.

Legacy SlBl наследует EntityPage, но хранит SB отдельно и не привязывает его как обычную EntityPage.Entity. Новое явное требование FORM-KEY-09 обязывает подключить presence по реальному составному ключу SlBl и текущим правам независимо от наследования. Fresh read/merge сохраняет local/raw; legacy exact dirty / case-insensitive trimmed comparison документируются раздельно, а сброс с перечитыванием выполняется через Cancel→Reset по FORM-KEY-01. Не заменять эти проверки presence-индикатором и не обещать compare-and-set, если процедура его не поддерживает.

Не выполнять общую Save-команду по выходу из поля/смене radio: такая автоматизация запускала бы реальную почтовую синхронизацию без предусмотренного подтверждения. Для readonly/disabled/busy общие keyboard handlers обязаны проверять доступность на момент команды, а сервер — права на Address/операцию независимо от UI.
