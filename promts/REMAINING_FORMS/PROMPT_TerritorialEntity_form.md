# Промт: реализовать TerritorialEntity_form — карточку территории

## Обязательное дополнение пользователя от 26.11.2026

Прочитай [ключевые требования FORM-KEY-01…09 / DR-01](../../docs/agents/editing-forms-key-requirements.md) и [общий план внедрения](../FORMS_UX_2026-11-26/00_ORCHESTRATOR.md). Они закреплены в корневом AGENTS и обязательны для всех существующих/новых форм и новых приложений. Новое поведение Cancel (Close/ResetAndStay/Continue), неразрушительный Refresh, Required-фон независимо от пустоты, focus/dirty/Enter, справка/тема каждой формы и presence сущности имеют приоритет над противоречащими историческими формулировками ниже.

Используй четыре общих задания и их владельцев; не создавай локальный CSS/JS/draft/presence/theme механизм. Для поиска/отчёта/диагностики сохраняется предметная семантика Cancel/Stop и нет фиктивного Save/DB reset/entity0. Новые требования расширяют применимые UI-ветви, права/CAS/DR-01 и уже исправленный Clayzor сохраняются. Внешние проверки остаются beta; фактически выполненные локальные проверки и применимость FORM-KEY фиксируются в handoff. Историческое описание source/legacy не означает приказ копировать его дефект или запускать уже реализованную форму заново.

## Задача и обязательные условия

Реализуй карточку территории, эквивалентную `Inventory/TerritorialEntity/TerritorialEntity_form.aspx`, с созданием/изменением, штатным удалением, списком телефонных кодов и доступом к существующему диалогу экспорта в 1С.

Обязателен [01_COMMON_RULES.md](01_COMMON_RULES.md). Прочитай актуальные AGENTS.md суперпроекта, Inventory, Entities, Controls. Срез сравнения: legacy `12a6efae7eb310adec06a57f6d80b8d9e76985b4`; новое Inventory `b3da274962c3c0811f71fbfe196f188ed3b5f659`. На нём карточки, Territory/TelCode CRUD и TerritorySelect не обнаружены в соответствующих деревьях новых репозиториев.

Сохраняй названия и порядок полей. Не превращай карточку в редактор географической модели иной структуры. Не реализуй внутренний механизм 1С заново: форма лишь открывает существующее приложение экспорта.

## 2. Маршруты, идентификатор и создание дочернего узла

Основной `/TerritorialEntity/TerritorialEntity_form` и alias `/TerritorialEntity/TerritorialEntity_form.aspx`. Сохрани смысл `URI_area_form`/`Config.territory_form`.

| Вход | Назначение |
|---|---|
| `id` | Числовой `КодТерритории`; Territory отдельно считает `"0"` новой записью |
| `parent` | Родитель при создании дочерней территории из дерева |
| `fromTree=true` | Источник открытия — дерево |
| `parentidp` | Страничный идентификатор получателя legacy-уведомления |
| `parentId`, `parentName` | Контекст родительской сущности/списка, **не** Parent территории |

Дерево открывает новую карточку с `id=0&parent=<selectedId>`; редактирование — с `id=<selectedId>`. Оно также передаёт fromTree и три поля родительского уведомления. Все параметры валидируй, query-string не является разрешением записи.

**Найденный разрыв legacy:** страница читает `parentidp/parentId/parentName`, но не присваивает `Request["parent"]` в `Terr.Parent`; `SetDefaultValues` пуст, а просмотренный `EntityPage` такого mapping также не делает. Свойство `IsParentTree` объявлено, но не используется. Поэтому нельзя считать создание дочерней территории доказанно правильным только по наличию caller URL.

В новой реализации обеспечь заявленный сценарием результат: новая территория создаётся под выбранным существующим родителем. Явно назначай Parent до записи, проверяй доступность и допустимость родителя, сохрани его при редактировании. Это документированное устранение разрыва, не новый UI-элемент. Не добавляй поле «Родитель» без требования; переподчинение относится к дереву.

Отдельно обработай отсутствие `id`, `id=0`, положительный существующий/удалённый ID, некорректное значение. Legacy при `Terr.Id==null` пишет «Код территории не передан» и завершает ответ; при недоступной записи выбрасывает DetailedException. Clayzor должен дать понятное состояние без редактирования отсутствующей записи и без случайного создания вместо редактирования.

## 3. Поля: порядок, подписи, binding

| № | Подпись из ru-ресурса | Контрол legacy | Сущность/БД | Правило |
|---:|---|---|---|---|
| 1 | Тип | `ddlTerritoryType` | `TerritoryCode / КодТТерритории` | Required в разметке; список из `ТипыТерриитории` |
| 2 | Код ОКСМ | `efOKCM` | `OKCMCode / КодОКСМ` | Nullable integer, без автоматического default |
| 3 | Название территории на русском языке | `efNameRus` | `TerritoryName / Территория` | Обязательно |
| 4 | Альтернативное название территории на русском языке | `efNameRusAlt` | `Territory1Name / Территория1` | Необязательно |
| 5 | Международное название территории на английском языке | `efNameInternEng` | `Caption` | Необязательно |
| 6 | Альтернативное международное название территории на английском языке | `efNameInternEngAlt` | `Caption1` | Необязательно |
| 7 | Аббревиатура | `efAbbr` | `Abbreviation / Аббревиатура` | Необязательно |
| 8 | Тел. код страны | `efTelCode` | `TelephoneCode / ТелКодСтраны` | Обязательно, **строка** |
| 9 | Направление | `efDirection` | `Direction / Направление` | Обязательно |

Не исправляй историческое написание таблицы/полей в SQL: `ТипыТерриитории`, `КодТТерритории`, `ТипТерриитории` подтверждены исходником.

`FillTerritoryTypeList` выполняет `SELECT КодТТерритории, ТипТерриитории FROM dbo.ТипыТерриитории`. Нет зафиксированного default типа и специального изменения полей при смене типа. Не додумывай defaults для страны/города.

`ValidateInput` проверяет русское имя, телефонный код страны и направление через `IsNullEmptyOrZero`: отсутствие и строка `"0"` не допускаются. Dropdown типа обозначен обязательным в UI, но в отдельном методе его проверки нет. В новой серверной валидации проверь также допустимость выбранного типа; не сохраняй 0/несуществующий FK. Остальные ограничения длины/NULL получи из реальной схемы, не из ширины HTML-контрола.

Код ОКСМ: legacy getter удаляет пробелы, точки и запятые перед int.Parse; setter положительные значения показывает, 0/отрицательные очищает. Код обязан оставаться числом с NULL для пустого, без культурозависимого превращения `1,2` в дробь. Зафиксируй решение нормализации и тесты для ru/en. В `EntityFieldInit` новый объект принудительно получает пустой efOKCM: не повторяй это на каждом render так, чтобы пользовательский ввод исчезал.

Под полями — список телефонных кодов территории; в footer — «Изменил/Изменено» через ClayChanged для существующей записи. Область Changed новой записи пустая. Даты отображаются по общему клиентскому timezone-контракту проекта.

## 4. Чтение и запись

Чтение: `SELECT_ID_Территории` — `SELECT * FROM Территории (nolock) WHERE КодТерритории=@id`. Не применяй вариант `SELECT_ID_Территории_Страна`: он ограничивает типом 2 и сломает регионы/города.

В snapshot entity загружаются ID, Parent nullable, тип, Территория/Территория1, Caption/Caption1, Аббревиатура, ТелКодСтраны, КодОКСМ nullable, Направление, Изменил, Изменено. Parent не является изменяемым bind-полем формы; не обнуляй его при частичном обновлении DTO.

`INSERT_Территория` и `UPDATE_Территория` сохраняют эти 10 полей:

`КодТТерритории, Территория, Caption, Территория1, Caption1, Аббревиатура, КодОКСМ, ТелКодСтраны, Направление, Parent`.

UPDATE фильтруется по `КодТерритории`. Все значения передавай параметрами. CRUD и read-model — Entities, никаких CRUD-прокси сервисов/inline SQL в форме.

**Получение нового ID требует отдельной проверки:** legacy `Territory.Save` вызывает ExecuteScalar, но `INSERT_Территория` не содержит OUTPUT/SELECT идентификатора. Не рассчитывай на неописанное поведение триггера. Прочитай схему, identity/default и триггеры на стенде; выбери правильный для них способ получения именно созданного ID. Проверь две конкурентные вставки. Нельзя использовать `MAX(КодТерритории)` или универсальное `@@IDENTITY` как угадывание результата.

Не делай приложение владельцем пересчёта L/R, если ими управляют реальные триггеры/процедуры. Установи DB-контракт перед добавлением и переподчинением. Иерархия после штатной записи должна оставаться целостной.

## 5. Команды и состояние

В панели: **ОК**, **Применить**, **Обновить**, **Отмена**; **Удалить** добавляется только для существующей доступной записи. `Редактировать` и `Перепроверить` убираются.

- **ОК**: сначала валидация. При неизменённом объекте закрыть без записи. Иначе сохранить и закрыть только после подтверждённого успеха.
- **Применить**: валидация/сохранение, остаться на форме. После INSERT заменить URL `id` на созданный и перезагрузить сохранённое состояние. Changed и дочерний список получают новый ID.
- **Обновить**: прочитать актуальную запись для сверки/merge, сохранив typed/raw draft; без скрытого discard. Для новой записи не читать несуществующий ID.
- **Отмена**: выполнить FORM-KEY-01 — «Закрыть без сохранения», «Отменить мои изменения и загрузить из БД», «Продолжить редактирование». Reset читает fresh до безопасного отказа, остаётся открытым; при ошибке ввод сохраняется. Для create — штатные defaults без INSERT. Ни одна ветвь не сообщает родителю ложное «сохранено».
- **Удалить**: подтверждение **«Вы уверены, что хотите удалить информацию о территории?»**. Ошибка остаётся на форме, успех обновляет связанный список и закрывает окно.

Legacy Save(false)/Save(true) не проверяет affected rows; новая реализация должна различать успешное изменение и конкурентно удалённую запись. Повторный клик/два параллельных сохранения не создают дубль. На SQL-ошибке исходный черновик не сбрасывается и окно не закрывается.

## 6. Удаление — только штатная семантика

`Territory.Delete` использует `SP_Delete_Территория = "master.dbo.sp_Delete_Территория"` с параметрами:

| Параметр | Legacy-значение |
|---|---|
| `@КодТерриторииУдаляемой` | Текущий ID |
| `@КодТерриторииЗамещающей` | 0 |
| `@Выполнить` | 1 |

Это не обычный `DELETE FROM Территории`. Процедура может проверять связи и управлять иерархией; её тело не входит в изученный набор. Не подменяй её каскадом и не добавляй выбор заменяющей территории без основания.

В legacy вызов передаёт `CommandType.Text` для строки имени процедуры. Проверь реальный execution contract и передай подтверждённый command type в новом DbManager; не копируй неоднозначный вызов. Действующий пользователь должен иметь необходимые права в той БД, где реально находится процедура. Не повышай права/не используй service account для обхода отказа.

## 7. Телефонные коды в карточке

Legacy `FillAreaList` строит `URI_telcode_search + "&areaid=" + id + "&clid=85&hidemenu=1"`. Контракт:

- список ограничен текущим `КодТерритории`;
- настройка клиента `clid=85` независима от общего дерева;
- главное меню вложенного списка скрыто;
- карточка кода — [PROMPT_PhoneCodeEntity_form.md](PROMPT_PhoneCodeEntity_form.md);
- новые/изменённые/удалённые коды отражаются в списке без потери несохранённых полей территории.

Используй общий ClayGrid/существующую metadata-инфраструктуру. Полный набор/порядок колонок и query-id определи по действующей `URI_telcode_search` и записи `Запросы`: исходник карточки их не задаёт. Не сочиняй новый список «похожих» полей.

Пока территория не сохранена и нет настоящего ID, не разрешай привязать телефонный код к `0`/другому объекту. После Apply нового объекта список должен активироваться на созданном ID. Это закрывает проблему legacy iframe, который строился даже для id=0.

## 8. Экспорт в 1С

`Get1SExportUrl` возвращает `Config.store_export1s_dir + "?DirOU=15&id=" + Entity.Id`; `store_export1s_dir` берётся из `URI_export_dir`. `DirOU=15` — подтверждённый discriminator справочника, не ID территории и не роль.

Кнопка/ссылка недоступна новой или отсутствующей записи. Для существующей:

1. Открывает существующий endpoint с текущим сохранённым ID.
2. Диалог появляется после загрузки содержимого iframe.
3. Заголовок **«Выполнить экспорт в 1С»**, действие **«Закрыть»**.
4. Пока диалог открыт, повторный клик не создаёт второй.
5. Закрытие освобождает состояние; следующее открытие работает.
6. URL и содержимое не формируются из непроверенного пользовательского ввода.

Экспорт не запускается автоматически при Save. Не вызывай реальный внешний экспорт во время проверки без разрешения; подготовь проверку маршрута/доступности и явно раздели её с выполнением операции. Если конфигурация недоступна, покажи понятную недоступность действия и занеси конкретное ограничение в handoff. Не заявляй, что экспорт реализован, подменяя его заглушкой.

## 9. Права, обновление родителя и интеграция с деревом

Специальной роли в коде карточки нет. Её нельзя произвольно назначить «только администратору». Подтверди реальные effective SQL permissions/ограничения под пользовательской identity. Используй Employee CurrentUser как источник доверенного контекста; свежая серверная проверка перед INSERT/UPDATE/DELETE/export согласно общим правилам, без собственной альтернативной системы HasRole.

Legacy `RefreshInventoryGrid` отправляет адресное SignalR-сообщение `v4_grid.refresh(0)`, только когда заполнены все `parentidp/parentId/parentName`. В Save этот метод явно не вызван; закрытие идёт через базовый V4DropWindow и его ParentPage/ParentGridId/ParentTreeViewId. Различай эти пути, не утверждай, что один window.refresh полностью им эквивалентен.

В Clayzor после успешного сохранения/удаления сообщай конкретному связанному parent о результате. Дерево обновляет затронутый узел/ветку, список — нужный набор; исходная карточка/выделение/фильтры не сбрасываются. Идентификатор parent из URL не должен позволять отправить данные произвольному пользователю. Открытие карточки — только clayOpen.

## 10. Приёмка

| Проверка | Критерий |
|---|---|
| Create root / create child из дерева | Правильный Parent, созданный ID, целостные L/R |
| ID отсутствует/0/невалиден/удалён | Явные разные состояния, без записи вместо ошибочного edit |
| Все 9 полей, ru/en, NULL ОКСМ | Значения round-trip, подписи и Tab в исходном порядке |
| Обязательное имя/код/направление/тип | Все ошибки видны до записи; черновик сохранён |
| Редактирование не-root территории | Parent не обнулён |
| Apply нового объекта дважды | Один объект, правильный ID в URL и дочернем списке |
| Две конкурентные вставки | ID не перепутаны |
| ОК без изменений | Нет лишнего DML, корректное закрытие |
| Cancel и Refresh с черновиком | Три исхода Cancel по FORM-KEY-01; Escape=Continue; Reset остаётся открытым, read/storage failure и N+1 не теряют ввод, Unknown сохранён; Refresh читает для сверки без discard |
| Отзыв прав после открытия | Запись/удаление/экспорт запрещены сервером |
| Ошибка сохранения/удаления | Нет success-path/закрытия, повтор возможен |
| Удаление территории со связями/детьми | Результат штатной процедуры, без самодельного каскада |
| Телефонные коды | Фильтр areaid, CLID85, новая запись после Apply, адресный refresh |

Handoff должен отдельно содержать: фактический DB-контракт INSERT/DELETE/иерархических триггеров; решение о legacy parent/ID-разрывах; metadata вложенного списка; доказанные права; результаты CRUD, build/test/browser; оставшиеся ограничения 1С. Страница не принимается как полный перенос при неподтверждённом создании ID или потере Parent.

Код ОКСМ нельзя молча округлить или трактовать как дробь на основании культуры браузера. Важен единый путь UI→validation→SQL→повторное чтение: недопустимое значение остаётся видимым для исправления, а не исчезает в setter. Названия и телефонный код страны сохраняют строковый характер и ограничения основного раздела.

Если для уже известного родителя или выбранной сущности подтверждён просмотр в readonly-режиме, сделай отдельную разрешённую ссылку. Не добавляй dropdown смены родителя и не обходи правило `ClaySelect.ReadOnly/Disabled`, которое блокирует также `ViewItem`. В этой карточке нет доказанной необходимости generic multi-select или editable-select; наличие соответствующих функций в Styles не расширяет домен формы. Вложенный список кодов также не означает, что в карточке надо создавать второе дерево территории: CL-08 принадлежит поиску/дереву, здесь используется его адресное обновление.

**Обязательный FORM-KEY-09:** существующая территория регистрируется по каноническому entity key и актуальным правам; новая без ID не создаёт общую группу0.
