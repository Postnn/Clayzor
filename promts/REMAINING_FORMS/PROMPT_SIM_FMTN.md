# Промт реализации SIM_FMTN — информация о FMTN

## Цель и границы формы

Реализуй отдельную форму, заменяющую legacy `Inventory/Equipment/SIM_FMTN.aspx`. Прочитай [общие правила](01_COMMON_RULES.md) и актуальные AGENTS. Это справочная запись **префикса FMTN**, короткого номера и описания. Она не редактирует SIM-карту оборудования, PIN/PUK, тариф, договор или дополнительные услуги SIM.

Перед работой пересверь текущие коммиты и чужие незавершённые изменения.

## 1. Маршруты и модель идентичности

Основной маршрут `/Equipment/SIM_FMTN`, совместимый `/Equipment/SIM_FMTN.aspx`. Вход `id` — **исходный строковый префикс**, а не код SIM или оборудования. Без `id` — создание; с существующим `id` — редактирование. Строка может содержать цифры, скобки и `_`, включая ведущие нули. Не применять `int` PK, numeric normalization, URL-конкатенацию без encoding или автоматическое превращение «0» в отсутствующий ID без явного правила.

При редактировании раздели `OriginalPrefix` и `DraftPrefix`. Префикс редактируется и участвует в UPDATE как новое значение, тогда как WHERE обязан использовать старый ключ. Это принципиальное поведение legacy. После успешной смены ключа внутренний ID и URL обязаны соответствовать новому префиксу; повторное сохранение/удаление не должно обращаться по старому ключу.

Перед загрузкой действий получи `Employee CurrentUser` в принятом first-load pipeline, изолируй draft по окну/circuit, отменяй устаревшие ответы при смене параметров или закрытии.

## 2. Поля и внешний контракт

Заголовок **«Информация о FMTN»**. Поля последовательно:

| Подпись | Сущность / SQL | Правила |
|---|---|---|
| Префикс FMTN: | `Sim.Name` → `ПрефиксFMTN` | Обязательный; MaxLength=11; regex `^[0-9()_]+$`; первый фокус |
| Короткий номер: | `Sim.ShortNumber` → `КороткийНомер` | Необязательный; MaxLength=20; непустое значение по regex `^\d+$` |
| Описание: | `Sim.Description` → `Описание` | Необязательный; TextBox, MaxLength=50 |

Legacy серверный `ValidateInput` проверяет `efPrefix.Value.IsNullEmptyOrZero()`: в том числе строка `"0"` считается неуказанным префиксом. Перенеси фактическую семантику helper, не приравнивай `"000"` к числовому нулю. Regex префикса допускает скобки без проверки их балансировки и underscore; не вводи требования «только цифры» или новую грамматику телефонии. `\d` короткого номера в .NET может включать Unicode digits: зафиксируй совместимое поведение и проверь реальную varchar-колонку/кодировку; не сужай на ASCII по догадке. Пустой короткий номер допустим.

Точные сообщения:

- «Необходимо указать префикс FMTN!»;
- «Префикс FMTN может содержать только цифры, круглые скобки и знак подчеркивания»;
- «Короткий номер может содержать только цифры».

Не полагайся на regex только в браузере: сервер повторяет ограничения. `SimFMTN` comments для Name упоминают varchar(20), а поле ограничено 11: пользовательский лимит 11 сохраняется; тип/максимум таблицы подтвердить отдельно. «Описание» остаётся однострочным полем, не произвольным длинным редактором.

Низ формы — `ClayChanged` с `Изменил`, `Изменено`. Новая запись не показывает `DateTime.MinValue`/фиктивного сотрудника. Используй `ClayEntityForm`, общие поля и toolbar, без копирования CSS `Kesco.SimEquipment.css` или локальных размеров контролов.

## 3. Команды и жизненный цикл

- **OK**: `SaveAndClose`, validation, при изменениях запись, затем обновление нужного родителя и закрытие. Если форма не изменена — закрытие без записи.
- **Удалить** только для доступной существующей записи. Подтверждение: «Вы уверены, что хотите удалить информацию о FMTN?». После успеха обновить родителя и закрыть.
- **Обновить**, **Отмена**, справка — стандартное поведение; несохранённые данные не теряются без подтверждения.
- Кнопка **Применить удалена** из панели legacy. `SaveApply` обработчик присутствует, но его UI закомментирован. Не добавляй видимую кнопку «Применить/Сохранить» только потому, что такой case есть в code-behind. Если внутренний compatibility handler оставлен, его сохранение без закрытия обязано корректно сменить ID, перечитать Changed и обновить родителя.
- Кнопки редактирования/перепроверки убраны; не добавляй отдельный режим read/edit.
- Ошибки Save/Delete отображаются, окно остаётся открытым; `RefreshInventoryGrid` и close выполняются только после успешной операции.

Dirty-state сравнивает все три поля с original. При неуспешной валидации/SQL draft и исходный ключ сохраняются. Отмена не должна отправлять write или сообщение об успешной записи.

## 4. Точный SQL-контракт и особенности upsert

Чтение: `SELECT * FROM vwSIMКартыFMTN WHERE ПрефиксFMTN = @id`; извлекаются `ПрефиксFMTN`, `КороткийНомер`, `Описание`, `Изменил`, `Изменено`. Один результат — запись; ни одного — not-found/new в зависимости от исходного режима; несколько — ошибка целостности, не выбор произвольной строки.

Сохранение legacy:

```sql
IF EXISTS(SELECT * FROM vwSIMКартыFMTN WHERE ПрефиксFMTN = @Id)
    UPDATE vwSIMКартыFMTN
    SET ПрефиксFMTN = @ПрефиксFMTN,
        КороткийНомер = @КороткийНомер,
        Описание = @Описание
    WHERE ПрефиксFMTN = @Id
ELSE
    INSERT vwSIMКартыFMTN(ПрефиксFMTN, КороткийНомер, Описание)
    VALUES (@ПрефиксFMTN, @КороткийНомер, @Описание)
```

`@Id` — исходный ключ; `@ПрефиксFMTN` — draft. `ShortNumber`/`Description` при пустом или null значении нормализуются в пустую строку. Delete: `DELETE vwSimКартыFMTN WHERE ПрефиксFMTN = @Id`.

Не добавляй в запись `КодОборудования`, PIN/PUK или телефон SIM. `evalLoad=true` в вызове формы не означает, что `SimFMTN.Save` реально перечитывает: override лишь выполняет SQL. В Clayzor явно обновляй состояние после успеха.

### Как обращаться с дефектами legacy

`IF EXISTS` не защищает от гонки двух одновременных вставок. Кроме того, удалённая другим пользователем существующая запись может попасть в ELSE и быть заново создана. Зафиксируй эти случаи как риски legacy; в новой реализации различай явный режим создания и изменение уже загруженной записи. Не восстанавливай конкурентно удалённую запись молча. При повторяющемся новом ключе показывай конфликт, сохраняя draft. Конкретную реализацию транзакции/unique constraint/concurrency проверяй по действующему представлению и триггерам; не выдумывай схему и не меняй её автоматически.

Данные/SQL — в Entities; форма без inline SQL, кастомной роли и CRUD-прокси. SQL Server 2008 R2: без `MERGE` как неподтверждённого способа исправления гонок, без `OFFSET/FETCH`, новых JSON-функций и других несовместимых добавлений. Сам факт поддержки конструкции на тестовом 2022 не доказывает эксплуатационную совместимость.

## 5. Родитель, SignalR и внешние открытия

Форма принимает **три независимых параметра**: `parentidp`, `parentId`, `parentName`. Legacy `RefreshInventoryGrid()` посылает через KescoHub сообщение только когда все три непусты:

- `PageId = parentidp`;
- `ItemId = parentId`;
- `ItemName = parentName`;
- адресат `SignaRReceiveClientsMessageEnum.PageId`;
- скрипт `<js>v4_grid.refresh(0);</js>`.

В Clayzor сохраняй семантику адресного обновления **конкретного экземпляра родительского грида**, а не broadcast всех Inventory окон или reload всей страницы. Не исполняй произвольный скрипт из входных параметров; новый typed notification/общий bridge должен передавать тип события и проверенный context. Если родитель остаётся legacy, адаптер совместимости обязан быть явным и проверенным. Не заменяй эти параметры одним `opener.refresh()` без доказательства эквивалентности. При отсутствующем родителе CRUD продолжает работать самостоятельно.

Инициация окна — общий `clayOpen`, URL encoding строкового префикса и parent-параметров, устойчивый window key. Успешный create/rename/delete вызывает ровно одно обновление; ошибки/отмена — ни одного. При получении уведомления родитель сохраняет активные фильтры, сортировку и страницу, насколько это поддерживает общий контракт.

## 6. Права и точки неопределённости

В `SIM_FMTN.aspx.cs` импорт Role присутствует, но проверки роли фактически не используются. `SimFMTN.Save/Delete` также не проверяют отдельную роль. Нельзя переносить сюда автоматически права PIN/PUK из EquipmentForm или называть роль 42 «SIM-специалистом». Установи права чтения/создания/изменения/удаления по подтверждённой SQL/приложенной политике; используй доверенный `CurrentUser`, свежую проверку перед write, fail-closed при ошибке identity/permissions.

DDL представления, ограничения uniqueness, каскады при смене префикса и бизнес-использование FMTN вне этой формы в изученных файлах не определены. До принятия требуется проверить схему/зависимости на доступном стенде и приложить результат. Наименование файла не даёт права изменять все SIM-строки с таким префиксом вручную. Меню/внешние URL могут быть заданы данными `Запросы`/`uri.local`; привязку маршрутов проверь на реальных настройках без массовой правки production.

## 7. Приёмочные сценарии

1. Новая запись, существующая запись и неизвестный ID дают разные состояния.
2. Строковый ID `001(2)_` переживает URL encode/decode, чтение, изменение и удаление без потери символов.
3. Префикс пустой и `0` отклоняются; допустимые скобки/underscore и ведущие нули сохраняются.
4. Лимиты 11/20/50: ровно предел допустим, превышение отклоняется сервером без обрезки.
5. Короткий номер пустой допустим; буквы/пробелы недопустимы; Unicode digits проверены с БД и зафиксированы.
6. Создание записывает только три нужных поля, Changed корректен после повторного открытия.
7. Изменение только описания/короткого номера не меняет префикс и не создаёт дубликат.
8. Переименование префикса обновляет строку по старому ключу, следующий read/delete использует новый.
9. Новый префикс уже занят: конфликт, исходная строка сохранна, draft не потерян.
10. Конкурентная вставка и удаление между read/save не создают ложный успех или молчаливое восстановление.
11. OK без изменений не делает UPDATE; visible Применить отсутствует, как в legacy.
12. Подтверждение удаления: Нет ничего не делает; Да удаляет одну запись и закрывает после успеха.
13. SQL error/отказ прав при Save/Delete не закрывает окно и не обновляет родителя.
14. Отмена/обновление dirty-form с выбором отказа сохраняет все три draft-поля.
15. Все три parent-параметра: адресный refresh нужного экземпляра, соседние окна не меняются.
16. Частично/полностью отсутствующий parent context: нет ошибочной отправки; самостоятельная форма работает.
17. Прямой write, отзыв прав после открытия, неизвестный CurrentUser и подмена исходного ключа обработаны сервером.
18. 320–480px, Tab, кнопки/Changed, повторное открытие и сохранение размера окна через общую инфраструктуру.

Handoff содержит source map, форму/сущности/SQL, поведение rename, подтверждённые ограничения и права, контракт parent refresh, результаты build/профильных тестов/CRUD/browser, реальные ограничения стенда. Не объявлять непроверенный вызов внешнего legacy SignalR подтверждённым. Не затрагивать текущий цикл исправлений EquipmentForm/Net и не коммитить/пушить без разрешения.

**Ограничения ввода.** Префикс и короткий номер остаются строками даже при вводе одних цифр: `001(2)_` и ведущие нули не проходят через `ClayNumber`. Лимиты 11/20/50 и .NET regex из основного раздела проверяются после вставки и на сервере. В legacy `TextBox.Validation` при ошибке возвращает `OriginalValue`; здесь сохраняй ошибочный текст для исправления. Наличие `jquery.ui.mask.js` в Styles не подтверждает маску на этих полях: реализация не должна вводить новую телефонную грамматику или молчаливое удаление символов. Не добавляй видимую «Применить» ради общего hotkey-контракта.

**Совместная работа.** Применимость CL-11 установи отдельно по реальному `EntityPage` / `Page` / SignalR contract и текущей инфраструктуре. Строковый ключ FMTN не обязан удовлетворять legacy условию `ItemId.ToInt() > 0`; наследование страницы само по себе не доказывает отображение presence.
