# Промт: реализовать PhoneCodeEntity_form — телефонный код территории

## Задача

Перенеси `Inventory/TerritorialEntity/PhoneCodeEntity_form.aspx` в Clayzor. Требуются создание, изменение реквизитов и удаление телефонного кода, выбор территории с правильным фильтром, повторяемый Apply и возврат в список.

**Ключ записи — строковое поле «ТелефонныйКод». Это не числовой surrogate ID.** Сохранение начальных нулей и исходного ключа при редактировании обязательно.

Следуй [01_COMMON_RULES.md](01_COMMON_RULES.md) и актуальным AGENTS.md. Анализ привязан к legacy `12a6efae7eb310adec06a57f6d80b8d9e76985b4` и Inventory `b3da274962c3c0811f71fbfe196f188ed3b5f659`. Формы/сущности/источника выбора территории в новом коде этого среза нет; общие ClayEntityForm, ClaySelect, ClayChanged и SQL infrastructure уже есть.

## 2. Маршруты и контексты

Поддержи `/TerritorialEntity/PhoneCodeEntity_form` и `/TerritorialEntity/PhoneCodeEntity_form.aspx`, сохрани существующие metadata-ссылки на карточку кода.

`id` — **строка**, совпадающая со значением `ТелефонныйКод`. Не используй `int.TryParse(id)` как универсальное условие существующей записи. Не удаляй начальные нули, не меняй текст при URL decode/encode и не подставляй ID территории.

`TelCode` наследует `Entity.IsNew`, которое проверяет только null/empty, а не `"0"`. Это отличается от Territory с отдельным override. Для new/edit нужен явный нормализованный контракт, согласованный с действительными ссылками метаданных; не переносить правило `id=0 — всегда новый` на все сущности проекта.

`parentidp`, `parentId`, `parentName` — контекст адресного legacy-refresh. `areaid` используется у списка кодов; **эта форма явно не читает areaid и не предзаполняет TerritoryId**. Перед реализацией проверь фактические AddParams/Defaults вызывающего списка и передай default территории через согласованный параметр. Не утверждай, что автозаполнение из areaid уже реализовано в code-behind.

Открытие из карточки территории/общего списка/расширенного поиска должно сохранять правильный parent. Обычный прямой URL также работает без обязательного opener.

### Выбор территории

`SetDefaultValues` задаёт `dbsTerritory.Filter.CodTTerritory.Value = "2,3,4"`. Default самого `DSOTerritory` — только `"2"`, поэтому простое переиспользование дефолта потеряет типы 3/4. Передай правильный фильтр явно.

Список читает `SELECT_Территории_Страны`, который фактически выбирает без фиксированного ограничения:

`КодТерритории, Территория, Caption, Аббревиатура, ТелКодСтраны FROM Территории`.

Ограничение по типам добавляет DSO. Caption используется для не-ru, русское имя — для ru. Расширенный поиск открывается по `Config.territory_search`, просмотр карточки — по `Config.territory_form`. Ссылки должны вести на перенесённые страницы. Не подменяй выбор свободным int/text input.

`FOptName.SQLGetClause` различает два вида запроса. Непустая строка целиком из цифр (`IsDigit`, а не проверка существования int-ID) сравнивается с **ТелКодСтраны**, а не с КодТерритории. Обычный текст ищется по двум полям **Территория и Caption** через `GetWhereStrBySearchWords(fields, WordsGroup)`. Поэтому общий TerritorySelect с одним поиском по отображаемому имени не покрывает legacy-контракт. Сохрани одновременное применение этого поиска и фильтра типов 2/3/4. Вместо legacy-конкатенации цифровой строки используй типизированный SQL-параметр по фактическому типу ТелКодСтраны; некорректный ввод/переполнение дают понятную ошибку, не превращаются в поиск территории по ID.

DSO задаёт сортировку по `Территория`. В `DBSTerritory.GetTerritories` вызов `territory.OrderBy(order => order.Name)` не материализован и не изменяет возвращаемую коллекцию, поэтому нельзя считать сортировку по локализованному Name установленным поведением. Сохрани проверенный порядок источника и локализацию подписей отдельно.

Сохранение кода должно повторно проверять TerritoryId и разрешённую область выбора на сервере. Для исторической записи с ныне недоступной/изменившей тип территорией покажи действующее сохранённое значение и явный конфликт, не очищай его молча при загрузке.

### Тип телефонной связи

`FillTelefoneTypeList` выполняет `SELECT КодТипаТелефоннойСвязи, ТипТелефоннойСвязи FROM dbo.ТипыТелефоннойСвязи`. Нельзя подменить этот справочник «типами телефонных номеров» из Tel: это другое понятие и другой ключ.

Legacy не задаёт сортировку/default. Установи фактический порядок справочника/контрола и не переименовывай элементы. PopupHeight=75 — визуальная настройка, не максимальное число типов.

## 4. Валидация

`ValidateInput` собирает все ошибки:

- территория не null/empty/`"0"`;
- телефонный код не null/empty/`"0"`;
- длина кода области не null/empty/`"0"`;
- тип связи — непустое значение;
- комментарий не обязателен.

Телефонный код не преобразуется в число. Не изобретай регулярное выражение международного номера: в этой форме нет подтверждённого правила «только E.164».

Длина кода — целое; ограничения БД/допустимые диапазоны прочитай из schema/check constraints. В entity setter допускает ноль, но UI-validation его запрещает — это не повод тихо разрешить ноль. Не добавляй самостоятельно правило `длина ≤ длина строки кода` без подтверждения БД/бизнес-контракта.

Для типа связи UI проверяет непустоту, не `IsNullEmptyOrZero`. Если в реальном справочнике есть код 0, нельзя удалить его исключительно по привычке; проверь существование записи и constraints.

Ошибки отображаются вместе с сообщением, что запись нельзя сохранить. Подписи ошибок соответствуют полям. Размеры HTML 100/20/400/420px не определяют SQL-длину данных.

## 5. CRUD и два legacy-разрыва

| Операция | SQL | Параметры/смысл |
|---|---|---|
| Load | `SELECT_ID_ТелефонныеКоды` | `WHERE ТелефонныйКод=@id`; Id SQL-параметра строковый |
| INSERT | `INSERT_ТелефонныйКод` | ТелефонныйКод, КодТерритории, ДлинаКодаОбласти, КодТипаТелефоннойСвязи, Комментарий |
| UPDATE | `UPDATE_ТелефонныйКод` | Обновляет территорию, длину, тип связи, комментарий; WHERE по исходному Id |
| DELETE | `DELETE_ТелефонныйКод` | `DELETE ТелефонныеКоды WHERE ТелефонныйКод=@ТелефонныйКод` |

INSERT в legacy квалифицирован `[Инвентаризация].[dbo].[ТелефонныеКоды]`, чтение/UPDATE/DELETE — без имени БД. Проверь, что текущая строка подключения ведёт к той же БД; не сохрани запись в одном каталоге, а перечитай из другого.

### A. Ввод изменённого ключа сейчас не сохраняется

В existing-mode textbox «Телефонный код» визуально editable, но `TelCode.Save` передаёт `@ТелефонныйКод=Id`, UPDATE не присваивает новое значение ключа. Ввод нового кода может визуально приниматься и затем исчезать после refresh.

Нельзя повторить это как успешное сохранение. Базовый перенос сохраняет установленную SQL-семантику **неизменяемого ключа**: отдели OriginalKey от draft и сделай существующий ключ явно неизменяемым/объясни ограничение в UI. Отметь это как устранение скрытого legacy-сбоя. Если действующий бизнес-сценарий требует переименования кода, сначала подтвердить FK/каскады/штатную операцию БД и реализовать её отдельно атомарно; не добавлять «DELETE+INSERT» по догадке.

### B. INSERT не возвращает ID

`TelCode.Save` вызывает ExecuteScalar и надеется получить `netId`, но SQL INSERT не содержит OUTPUT/SELECT. Здесь известен естественный ключ: после успешной вставки идентификатор должен быть подтверждённо сохранённым телефонным кодом. Прочитай constraints/триггеры на стенде, выполни корректное read-back и установи Id только после успеха. Не считай `null` от ExecuteScalar доказательством неуспеха вставки и не повторяй её автоматически.

Обязательный тест: создать → Применить → изменить комментарий → Применить. Вторая операция должна быть UPDATE одной и той же строки, не повторный INSERT с duplicate key. Ключ в URL должен быть правильно encoded.

`Comment??""` — установленная нормализация legacy. Для остальных колонок используй реальные DB-типы и NULL-семантику. CRUD/read-model размещай в Entities; не создавай отдельный service-прокси.

## 6. Команды, отсутствие записи и сохранение черновика

Панель использует **ОК**, **Применить**, **Обновить**, **Отмена**, а для существующей доступной строки — **Удалить**. «Редактировать»/«Перепроверить» удалены.

- ОК валидирует; при неизменённой записи закрывает без DML, иначе сохраняет и закрывает после успеха.
- Применить сохраняет, обновляет URL новым Id при вставке и перечитывает сохранённое состояние, оставаясь на форме.
- Refresh и Cancel наследуют подтверждение при изменённом объекте. Отказ от подтверждения сохраняет draft.
- Удаление спрашивает **«Вы уверены, что хотите удалить информацию о телефонном коде?»**; success обновляет parent и закрывает, ошибка оставляет форму.
- Не найденная existing запись: скрытие редактируемого содержимого, предупреждение **«Телефонный код {id} не найден или недоступен!»**, затем `NotFound` → обновление списка и закрытие. В Clayzor допустимо явное состояние unavailable с командой закрытия, но не пустая карточка создания.

Не закрывай окно/не отправляй успех при SQL exception, нулевом affected-row из-за конкурентного удаления или проверенном отказе прав. Введённый комментарий и остальные поля должны пережить исправимую ошибку. Повторный клик защищён от параллельной записи.

## 7. Права и parent refresh

Именованной роли в этом code-behind и entity нет; её нельзя выдумать. Проверь реальные разрешения SQL на таблицу и проектный domain policy. CurrentUser загружается до доступности UI, а перед INSERT/UPDATE/DELETE выполняется свежая серверная проверка в Entities в доверенной identity. Смена переданного TerritoryId не должна обходить ограничения.

`RefreshInventoryGrid` посылает `v4_grid.refresh(0)` по `parentidp/parentId/parentName` только при заполнении всех трёх. Явный вызов есть в Delete/NotFound; save/close дополнительно зависит от общего `V4DropWindow` и parent-grid contract. Реализуй адресное обновление в Clayzor без full-page reload и без потери черновика карточки территории.

Не принимай произвольный callback URL как разрешение серверу отправить запрос. Для современных callers используй общий проверенный канал, для оставшихся legacy — явный совместимый адаптер.

Соблюдай действующий Select AGENTS: AutoSelectSingle/Exact только Enter/blur непустого запроса, не кнопка списка; hover не меняет keyboard index; промежуточный null при Clearable не считается подтверждённой очисткой. Keyboard access к actions и возврат фокуса реализуются общим CL-04. Тип телефонной связи остаётся полным закрытым списком своего источника, а не свободным editable-select. Для readonly территории, если этот режим нужен по правам, разрешённый drilldown показывается отдельной ссылкой; глобальное разрешение ViewItem в ReadOnly противоречит текущему контракту.

Не переносить `TextBox.Validation` с возвратом ошибочного значения к OriginalValue и legacy numeric fallback через float. Пользователь должен видеть и исправить введённое значение. Исправимая ошибка не изменяет исходный ключ и не отправляет уведомление об успехе.
