Реализуй самостоятельную форму `Inventory/Equipment/PhonePoolAtribute_form.aspx` в Clayzor. Применяй [общие правила](01_COMMON_RULES.md) и актуальные AGENTS. Название legacy содержит `Atribute` с одной `t`: совместимый URL сохраняет это написание.

## 1. Вход, ключ и отличие новой записи от недоступной

Маршруты `/Equipment/PhonePoolAtribute_form` и `/Equipment/PhonePoolAtribute_form.aspx`; query `id`. Legacy явно выполняет `HttpUtility.UrlDecode(Request.QueryString["id"])` и конструктор разбирает две части:

1. Сначала `id.Split(':')`, ровно две части.
2. Если не получилось — разделитель `char(31)` (unit separator), также ровно две части.
3. Иначе `LogicalException`: «Не удалось установить идентификатор сущности Атрибут пула».

Первая часть — код пула, вторая — строковый тип атрибута, varchar(50). Сохрани прием совместимых форм ID, включая URL-encoded `:` / `%1F`. Не декодируй повторно произвольные escape-последовательности: проверь реальную framework decoding boundary и тестами зафиксируй однократный семантический разбор. Нельзя скармливать строку целиком в `int.Parse` или переносить в generic entity с int PK. Используй типизированный ключ из двух полей.

Наличие самого значения определяется отдельным COUNT по паре. Поэтому **корректный существующий пул + существующий тип + отсутствующее значение = разрешённый новый атрибут**. Legacy вызывает `Load()` и в таком случае ставит `Unavailable=true`, одновременно `IsNew=true`; новую реализацию нельзя автоматически блокировать из-за этого исторического флага. Ошибка чтения/недостаток прав не равны отсутствию строки. Некорректный ID, отсутствующий пул, отсутствующий тип и недоступный родитель — отдельные ошибки, не повод создать произвольные данные.

`Entity.IsMultiId=true` препятствует повторной стандартной загрузке по одному ID; `IsCollaborateWork=false`. Сохрани изоляцию черновика и не копируй legacy shared mutable entity между пользователями.

## 2. Вид формы и команды

Заголовок **«Значение атрибута пула»**. Ровно четыре поля в указанном порядке:

| Подпись | Legacy control | Данные и режим |
|---|---|---|
| Пул телефона: | `tbPool` TextBox | `PhonePool.Name`, read-only |
| Тип атрибута: | `tbType` TextBox | Исходная строка `PoolAttribute.Type`, read-only |
| Описание: | `tbDescription` TextArea | `PhoneAttributeType.Description`, read-only |
| Значение: | `tbValue` TextBox | Единственное изменяемое поле; MaxLength=150 |

Начальный фокус — «Значение». `Changed` показывает автора и время именно записи значения, а не пула/типа. Для нового значения нижняя область пуста. Пустое значение не помечено обязательным в legacy и не равнозначно команде Delete.

Кнопки:

- `OK` → SaveAndClose; при отсутствии изменений закрывает без SQL.
- `Применить` → Save (legacy не переименовывает эту базовую кнопку в «Сохранить»).
- `Удалить` только при существующем значении, с подтверждением «Вы уверены, что хотите удалить значение атрибута {Тип}?». Tooltip: «Удалить запись со значением атрибута пула».
- Стандартные `Обновить`, `Отмена`, справка — через общий каркас, сохранение предупреждения о dirty-state.
- `Редактировать` и перепроверка удалены.

Используй `ClayEntityForm`, `ClayToolbar`, `ClayTextBox`, `ClayTextArea`, `ClayChanged`; не переносить фиксированную ширину 400px, локальный CSS и `window.resizeTo`. Сообщение об ошибке должно быть читаемо в текущем окне и на 320–480px.

## 3. Чтение и запись

Подтверждённые запросы работают с `vwАтрибутыТелефоновПула`:

| Операция | SQL / параметры | Семантика |
|---|---|---|
| SELECT пары | `SELECT_АтрибутыТелефоновПула_ID`: `@КодПулаТелефонов`, `@ТипАтрибутаТелефона` | Возвращает `Значение`, `Изменил`, `Изменено` |
| EXISTS | `SELECT_АтрибутыТелефоновПула_Количество` с обоими параметрами | Наличие строки, не непустого значения |
| INSERT | `INSERT_АтрибутыТелефоновПула` | Вставить код пула, строковый тип и значение |
| UPDATE | `UPDATE_АтрибутыТелефоновПула` | Меняет только `Значение` в указанной паре |
| DELETE | `DELETE_АтрибутыТелефоновПула` | Удаляет только указанную пару |

Legacy `HasValue()` определяет `_isNew` в конструкторе, `Save` выбирает INSERT/UPDATE и после успеха сбрасывает `_isNew=false`. Не используй слепой upsert, превращающий конкурентное удаление существующей записи в незаметное восстановление. Конкурентная вставка такой же пары должна давать понятную коллизию и сохранять черновик. Нулевой результат UPDATE/DELETE требуется отличать от успешной записи; конкретный механизм подтверждай по представлению и триггерам, не предполагай доступный rowversion.

Новая сущность/key/read helpers — в Entities; SQL только SQLQueries; Web-форма хранит draft и UI. `PhonePoolLookup` можно использовать для имени пула, но не подменять нужную серверную проверку родителей полученным из браузера display name. У типа дополнительно есть `ValuesSource` (tinyint), однако **эта форма его не использует**: не изобретай dropdown, генератор или правила допустимых значений по этому полю. Длина описания типа в legacy comments 1000; поле только для показа.

Проверки write-path: корректные составные ключи, реальное существование пула/типа, лимиты по подтверждённой схеме, доступ текущего сотрудника, сохранение неизменяемой пары. При SQL error retain draft; не сбрасывать dirty-state, не закрывать, не извещать родителя об успехе.

## 4. Обновление родителя и совместимость

После **успешного Save** вызывается `RefreshOpenerWindow()`, который, если доступно, выполняет `opener.refresh()`. Затем:

- «Применить» для новой записи обновляет URL `id=PoolId:Type`, перечитывает форму и оставляет её открытой.
- «Применить» существующей записи также перечитывает данные.
- OK закрывает окно.
- Delete после успешного SQL закрывает форму; явного `RefreshOpenerWindow()` в `DeleteData` нет. Общий механизм закрытия/обновления родителя нужно сопоставить, а не утверждать, что отсутствующий явный JS означает отсутствие refresh вообще.

Обеспечь проверяемое уведомление только адресованному родительскому окну через общий Clayzor механизм; не перезагружай весь родитель и не теряй его фильтры/черновик. Legacy callback-form содержит `escaped`, `control`, `multiReturn`, `value` и action из `callbackUrl`; это транспорт совместимости, не разрешение отправлять данные на произвольный callback URL. Используй общий origin/request correlation контракт из этапа Finder. Страница должна работать и без opener.

Открытие — только `clayOpen` с устойчивым ключом на форму/сущность. Для составного ID всегда корректное URL-encoding, никаких JS-конкатенаций с неэкранированным типом. Проверь источники ссылок в динамических настройках грида/`uri.local`: исходники не доказывают конкретную запись меню, её нельзя придумывать.

## 5. Права, отсутствие внешних эффектов и legacy особенности

Отдельной роли в форме/PoolAttribute CRUD не найдено. Не присваивай роль администратора телефонии по названию задачи. Подтверди реальную политику SQL-представления и текущего приложения, используй `Employee CurrentUser`, повторно проверяй доступ непосредственно перед сохранением/удалением, сохраняй SQL identity текущего пользователя. В отсутствие подтверждённых прав — явная блокировка записи, не молчаливое расширение доступа.

Никакой явной отправки конфигурации на телефон, HTTP к АТС, сброса аппарата или массового обновления всех пулов этот code-behind не выполняет. Возможные триггеры представления требуют проверки в БД; наличие/отсутствие таких эффектов по репозиторию утверждать нельзя. Не добавляй сетевые команды по аналогии с EquipmentForm.

Не переносить дефекты базовой реализации: HTML/JS-инъекции в Type, двойное URL decoding, ложный успех после конкурентного удаления, смешение отсутствующего значения с несуществующим пулом. Различие пустой строки и NULL требуется зафиксировать по схеме; legacy передаёт `Value` как есть, комментарий у колонки — varchar(150), not null.

## 6. Матрица приёмки

1. Существующая пара: верные имя пула, тип, описание, значение и Changed.
2. Валидные родители без значения: новая запись доступна; Changed пуст, Delete отсутствует.
3. ID с `:` и с `%1F` одинаково выбирают правильную пару; тип со спецсимволами не ломает URL/JS.
4. Отсутствующий ID, один/три сегмента, пустой пул/тип, неверный numeric pool ID и неизвестные родители корректно отклоняются.
5. Пустое значение сохраняется в допустимой DB семантике; оно не удаляет строку.
6. 150 символов, превышение лимита, unicode/кодировка проверены без молчаливой обрезки.
7. Поля пула и типа read-only; подменённый запрос не изменяет чужую пару.
8. OK без изменений закрывает без UPDATE; OK после правки пишет и закрывает.
9. Применить новой записи устанавливает канонический ID, затем повторное применение не делает второй INSERT.
10. Применить существующей записи перечитывает Changed и очищает dirty-state только после успеха.
11. Delete: отказ подтверждения ничего не меняет; согласие удаляет ровно одну пару.
12. Отмена/обновление с dirty-state позволяют отказаться от потери данных.
13. SQL error при чтении не считается «новой строкой», при записи сохраняется draft и нет success notification.
14. Два окна вставляют одну пару; UPDATE после удаления; DELETE после удаления — обработаны явно.
15. Право отозвано после открытия и прямой серверный write без рендера запрещены.
16. Родитель получает адресное обновление после сохранения; другое окно не обновляется; без opener ошибок нет.
17. Работа с общим callback проверена после исправления bridge Finder; произвольный callbackUrl не исполняется.
18. Адаптивность, Tab, длинные тип/описание/значение и единый стиль общих контролов.

Handoff: точные маршруты и composite key, источники меню/ссылок, SQL/права, различение new/not-found/denied, результаты сценариев и ограничения БД. Не менять текущую работу по EquipmentForm/Tel/Net и не коммитить/пушить без авторизации.

**Presence FORM-KEY-09 и изоляция:** в `EntityInitialization` явно установлено `IsCollaborateWork=false`. Сохрани отдельный draft каждого окна/circuit; не подписывай эту форму на broadcast редактируемого значения и не переноси shared mutable entity. Это не отменяет адресный ответ своему opener после успешной операции и проверки SQL-конфликтов составного ключа. Несмотря на этот legacy opt-out, современный редактор обязан показывать других сотрудников по полному составному ключу через общий presence; это не broadcast значений.

Единственное изменяемое поле — строка значения. Цифровое содержимое не превращает её в `ClayNumber`; новый input mask не подтверждён. Не добавляй выбор другого пула/типа для удобства фокусировки. Если подтверждённый проектный сценарий требует просмотра пула или типа, используй отдельную разрешённую ссылку с достоверным ID: текущий контракт `ClaySelect.ReadOnly/Disabled` не позволяет включить `ViewItem` снятием запрета редактирования. Сами readonly TextBox legacy не доказывают существование такого перехода.

Управление фокусом должно завершаться при закрытии формы; отказ от подтверждения отмены/обновления возвращает пользователя к сохранённому вводу. Enter не означает Delete; подтверждение удаления и пользовательское закрытие диалога не должны считаться одним положительным исходом. Наличие общей инфраструктуры не добавляет новые кнопки и не меняет подтверждённую семантику пустой строки.
